# Weekly GitHub Plan

Dates use the project timezone (America/New_York). Each task should be implemented on a feature branch, reviewed by the other member, and merged through a pull request. Both members need their own sustained, meaningful commits; do not commit on behalf of a teammate.

## Working agreement

- One scoped concern per branch and PR.
- Prefer several small, explainable commits over one large upload.
- Every PR states what changed, how it was verified, and what remains uncertain.
- The non-author reviews the diff and runs at least the smoke test.
- Do not merge code that either teammate cannot explain.
- Do not commit audio, checkpoints, credentials, notebook outputs, or generated caches.
- Record failed experiments in a compact results table instead of deleting their history.

Avoid generic messages such as `update`, `final`, or `changes`.

## Pull-request checklist

- [ ] The change answers one stated question.
- [ ] Data split and random seed are explicit.
- [ ] No test-set tuning occurred.
- [ ] Tests or smoke commands are included.
- [ ] Results are generated by code, not typed from memory.
- [ ] Limitations and failed cases remain visible.
- [ ] No secret, private data, large audio, or model checkpoint is tracked.
- [ ] AI assistance is acknowledged when material.
- [ ] The reviewer can explain the change.

## Presentation checkpoints

Because presentation is 60% of the course grade, update the story continuously:

- End of Week 2: one motivation slide and one data/split slide.
- End of Week 4: first honest baseline figure.
- End of Week 6: freeze the main result and claim.
- End of Week 7: freeze error cases, limitation slide, and demo behavior.
- Week 8 onward: rehearse for clarity and timing rather than adding uncontrolled models.
